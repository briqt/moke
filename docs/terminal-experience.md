# 终端渲染架构：度量、落位与决策记录

本文记录 moke 终端渲染层的几何度量与字形落位设计取舍。

代码落点：

| 位置 | 职责 |
|---|---|
| `terminal-view/.../GridMetrics.java` | 格子几何的**纯计算**（列宽、行高、基线、字形落位），无 Android 依赖，单测全覆盖 |
| `terminal-view/.../TerminalRenderer.java` | 把 `GridMetrics` 的结果画到 Canvas |
| `terminal-view/.../TerminalView.java` | 行列重算、命中测试、PTY 尺寸同步 |
| `app/.../terminal/FontRepository.kt` | 主字体 + 回退链合成（`Typeface.CustomFallbackBuilder`） |
| `app/src/test/.../BundledFontMetricsTest.kt` | 内置字体度量护栏（构建期发现"回退字体不合格子"） |

---

## 1. 目标

**格子上的一切必须可解释。** 用户看到"字被拉长""图标变瘦""中文字距被拉开"，都应该能在代码里
指到一个具体原因；反过来，任何"看起来差不多"的魔数都不允许存在。

moke 与 Termux 的处境不同：Termux 只用系统等宽字体，什么都不用管；moke 允许用户换字体、调行距字距、
还要内置 CJK 与图标回退。**自由度越高，度量一致性越要自己守。**

---

## 2. 现状审计（实测数据）

### 2.1 一次真实的失真：图标被压窄 40%

用户报告"换行距后图标缩得很窄"。定位到上游 `TerminalRenderer.drawTextRun()`：

```java
mes = mes / mFontWidth;
if (Math.abs(mes - runWidthColumns) > 0.01) {
    canvas.scale(runWidthColumns / mes, 1.f);   // 只缩 X，不缩 Y
}
```

这段代码的语义是"把一段文字的实测宽度硬掰成它占的列数"。只要字形的 advance 与格子不等，字形就会被
**横向拉伸或压缩**。实测（`res/font` 内文件逐字形解析）：

| 字体 | 所有字形 advance | 用途 |
|---|---|---|
| `jetbrains_mono.ttf`（默认主字体） | 0.600em | 定格子 |
| `nerd_symbols_design.ttf`（pictograph 回退） | **1.000em**（devicon 墨迹 1.000×1.000em） | 图标 |
| `nerd_symbols_mono.ttf`（线画回退，JetBrainsMono NFM） | **0.600em**（powerline 墨迹 1.334em 高，正好填满 1.32em 行盒） | powerline / box / 块元素 |
| `noto_sans_sc.otf`（CJK 回退） | 汉字统一 **1.000em**，Latin 比例（`X`=0.573em） | 中文 |
| `noto_sans_symbols2.ttf`（符号回退） | 不统一（0.586–1.0em） | 杂项符号 |

于是：

- **图标** 1.0em 落进 1 格（0.6em）→ `canvas.scale(0.6, 1)` → 横向压到 60%。
  `U+F015`（home）墨迹原为 1.002×0.889em，压完 0.60×0.889em，宽高比从 1.13 掉到 0.67。
  （第一版修法改成"等比缩小"，图标不再变形但仍只有 60% 大小——见 ADR-2 的补正。）
- **中文** 1.0em 落进 2 格（1.2em）→ `canvas.scale(1.2, 1)` → 横向拉宽 20%。
- **字间距**：上游用 `Paint.setLetterSpacing` 加宽 advance，而加宽后的 run 又被上面那段代码缩回列宽，
  两者抵消——滑块的净效果是"把字压窄"，而不是"拉开字距"。

同一次截图测量还给出了格子比例：moke 光标块 23×65px（行距 1.3），Termux 22×48px。字形墨迹尺寸一致，
差异全在行高——这条线索把问题引到"行距倍数 × 字体自然行距"，进而发现了 `coerceIn` 把陈旧偏好夹到
滑轨端点的问题（见 CHANGELOG `[未发布]`）。

### 2.2 其余可疑点

| 现象 | 原因 |
|---|---|
| 列宽靠 `measureText("X")` 单点取样 | 'X' 一旦是异类字形（非等宽字体、可变字体实例），整个网格就歪 |
| 行距倍数的余量全在基线之下 | 文字贴住行顶，行距调大时视觉重心偏高 |
| 连字（`liga`/`calt`）默认开启 | 连字把多个字符合成一个字形，run 的 advance 与列数脱钩，只能靠 2.1 的拉伸兜底 |
| 字形定位无亚像素 | 位置被舍入到整像素，网格对齐有 0.5px 级误差 |

---

## 3. 三条原则

1. **格子是唯一真相。** 列宽、行高只由字体度量与用户的字距/行距倍数决定；任何字形都不参与决定格子大小。
2. **渲染器不撒谎。** 字形按自己的 advance 出墨。宽了等比缩小，宽字形（2 列）窄了等比放大填满跨度，
   其余居中——**永远不做只缩 X 的变换**。宁可让一个不匹配的字体看起来略小，也不让它变形。
3. **回退字体必须与格子同度量。** 这条靠构建期测试守住（`BundledFontMetricsTest`），不靠运行时补救。

---

## 4. 决策记录

### ADR-1 列宽取 ASCII advance 的众数，不取 `measureText("X")`

- **问题**：单点取样对"非严格等宽"的字体不稳健。
- **选项**：(a) 继续用 'X'；(b) 取 ASCII 样本的众数；(c) 取样本平均值。
- **决定**：(b)。分箱精度 1/64px；平票取更宽的箱子（格子宁宽勿窄）。
- **理由**：等宽字体下众数就是那个唯一值（与取样哪个字形无关）；个别异类字形被自动忽略；
  比例字体退化成"最常见字宽"，至少不会因为一个极值崩掉。平均值会被 'i'/'W' 拉偏，不适合定格子。
- **代价**：构造时多量 95 个字形（一次性，可忽略）。
- **测试**：`GridMetricsTest.cellWidth*`。

### ADR-2 字形永不横向拉伸

- **问题**：上游用 `canvas.scale(k, 1)` 把 run 硬掰到列宽，图标变瘦、CJK 变宽。
- **选项**：(a) 保留拉伸；(b) 等比缩小；(c) 不缩放直接溢出。
- **决定**：等比缩放 + 居中（`GridMetrics.placementScale` / `centerOffset`）。
- **理由**：变形的字形在任何场景下都是错的；等比缩放至少保住比例。溢出（(c)）会让相邻格子互相压字，
  在 `字距 < 1.0` 的压缩模式下完全不可读。
- **影响**：cell 与 advance 相等的字体（等宽字体 + 同格回退）**零变化**——这是绝大多数情况，
  所以这次改动对默认观感是中性的，只在"字体不匹配"时生效。
- **补正（第二版）**：第一版对"宽于格子"一律等比缩小，结果 Nerd 图标只剩 60% 大小——用户实测
  "yazi 里的图标偏小"。改为按设计尺寸画、由 `centerOffset` 两侧对称溢出（偏移为负），只有压缩模式
  （字距 < 1，格子比字形还窄）才缩小。
- **补正（第三版）**：完全按设计尺寸溢出会吃掉邻居半格（1em 图标在 0.6em 格子里两侧各 0.2em）。
  现给溢出设上限：**每侧 0.15em**（`TerminalRenderer.ICON_OVERFLOW_EM_PER_SIDE`，约四分之一格）。
  默认配置下 1em 图标画成 **0.9em**——保住九成设计尺寸，横向只挤 0.15em，而图标后面通常本来就跟着
  空格。缩放锚点也从"格子左缘"改成"格子中心"，保证缩小后的图标仍然居中。

### ADR-3 宽字形（2 列）填满它的跨度

- **问题**：回退 CJK 字体常常是 1.0em/字，而 2 格跨度是 1.2em（格子 0.6em）。按原尺寸画，
  每个汉字两侧各多 0.1em 空隙，整段中文看起来像被拉开了字距。
- **决定**：占 2 列的字形等比放大到填满跨度。
- **理由**：占 2 列就意味着"我需要两格"，填满才符合网格语义；放大是等比的，不破坏字形。
  窄字形则相反——它本来就只要一格，放大只会挤到邻居，所以只缩不放。
- **上限**：放大不超过 1.5 倍。正常的不匹配是 1.0em 字形对 1.2em 跨度（+20%）；超过 1.5 倍说明那个
  "宽字形"的 advance 远小于它的列跨度（某些字体的 emoji 只有 0.6em advance 却声明占 2 列），
  此时吹到 2.4 倍只会得到一屏巨大的表情符号——宁可保持原尺寸居中。
- **彻底解法**：用 1 字 1.2em 的 CJK 字体（Maple NF CN、Sarasa Mono）。Release 构建的默认回退
  就是 Maple NF CN；Debug 用内置思源黑体子集（1.0em），由 ADR-3 兜底。

### ADR-4 字距倍数缩放格子宽，不用 `Paint.setLetterSpacing`

- **问题**：固定网格里，"字间距"若靠加宽 advance 实现，会被列宽归一化抵消（见 2.1）。
- **决定**：`字距倍数 × 格子宽`。字距 > 1 时字形两侧留白变多（视觉上就是拉开字距），
  字距 < 1 时格子窄于字形，字形按 ADR-2 等比缩小（压缩模式）。
- **影响**：`字距` 现在会改变列数（和改字号一样），这是网格语义的必然结果，已写进 CHANGELOG。

### ADR-5 行距倍数的余量上下对半分

- **问题**：上游把多出来的行高全放在基线之下，文字贴住行顶。
- **决定**：`halfLeading = (行高 - 自然行距) / 2`，基线整体下移这么多。
- **理由**：排印惯例（半行距）；行距 > 1 时文字在行内视觉居中。行距 ≤ 1（压紧）时不动基线——
  压紧时字形本来就在互相靠拢，上移只会让降部更难读。
- **影响**：行距 = 1.0 时 `halfLeading = 0`，**零变化**。

### ADR-6 连字保留，但按 shaping 后的宽度落位

- **问题**：连字把多个字符合成一个字形，逐字累加 advance 会算出比实际更宽的值，run 因此被误判为
  "比格子宽"而缩放——这正是上游把连字渲染成拉伸形状的原因。
- **决定**：保留 `liga`/`calt`（不设 `setFontFeatureSettings`），一段文字的宽度改成在 flush 时
  用 `measureText(line, start, count)` **按 shaping 结果量一次**。
- **理由**：等宽连字字体（JetBrains Mono、Fira Code、Maple…）的连字字形 advance 正好等于它替换掉的
  列宽之和（`->` 两列 → 1.2em），所以 shaping 后的宽度仍然与列跨度吻合，不需要任何缩放。
  这样连字与网格可以共存——Termux 做不到这一点（它没有 shaping 概念，连字只会被拉宽）。
- **边界**：连字不跨样式边界（run 按样式切分），也不跨宽窄字边界；光标/选中落在连字的某一格时
  该连字会退化成独立字形（与 kitty 之外的多数终端一致）。
- **代价**：每帧每 run 一次 `measureText`（原本是逐格查表）。短 run 上可忽略，换来的是连字正确。

### ADR-7 回退字体按「字形类别」分两段，各自用对的度量

- **问题**：Nerd 图标的度量有两种互斥的设计，选错哪一种都会难看：
  - 按 **1em 方形**设计（`Symbols Nerd Font`）：图标大小与桌面终端一致，但 advance = 1em ≠ 格子
    0.6em，会溢出相邻格；powerline 也只有 1.011em 高，在 1.32em 行盒里露行缝。
  - 按**格子**设计（`NFM` mono 变体，advance = 0.6em）：powerline 1.334em 高、正好填满行盒，
    但图标被压到 60%——用户报的"图标偏小"就是这么来的。
- **决定**：分两段回退，按覆盖范围分工：
  1. `nerd_symbols_design.ttf`（advance = 1.0em，pictograph 用）——devicons / Font Awesome / git 图标；
  2. `nerd_symbols_mono.ttf`（advance = 0.6em = 默认主字体，线画用）——powerline / box drawing / 块元素。
- **前提**：两段的覆盖必须互补。`Symbols Nerd Font` 本身没有 box drawing / 块元素 ✓，但它**有**
  powerline（U+E0A0–U+E0D7）。所以对设计尺寸字体做了一次**最小 cmap 手术**：只摘掉这一段码位
  （28 组 → 22 组，原地改写，字形轮廓未动），让 powerline 落到格子度量字体。
- **测试**：`BundledFontMetricsTest` 断言设计尺寸字体覆盖 pictograph 且 advance = 1em、格子度量字体
  覆盖线画且 advance = 主字体、两者的覆盖互补（线画不得被设计尺寸字体认领）。
- **代价**：APK 多一个 2.5MB 字体（替换掉旧的 2.5MB，净增 2.5MB）；字体被修改，许可说明已注明。

### ADR-8 亚像素文本定位

- **决定**：`Paint.setSubpixelText(true)`。
- **理由**：字距倍数会产生小数像素位置，亚像素定位让字形落在它该在的位置，而不是被舍入。

## 5. 验证方法

| 层次 | 验证手段 |
|---|---|
| 格子几何与缩放计算 | `terminal-view` 的 `GridMetricsTest`（纯 JVM 单元测试，无 Android 依赖） |
| 内置字体度量护栏 | `app` 的 `BundledFontMetricsTest`（直接解析 TTF 的 head/hhea/hmtx/cmap） |

| 集成与构建 | CI：`./gradlew assembleDebug testDebugUnitTest lintDebug` |
| 真机渲染人眼验收 | `bash scripts/terminal-grid-check.sh`：标尺 / 2 格块画 / Nerd 图标 / powerline 与线画 / CJK / 连字，六段各带"通过标准" |
